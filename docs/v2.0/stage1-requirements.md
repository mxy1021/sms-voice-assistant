## 范围与行为

| 编号 | 仅播报验证码 | 精简验证码播报 | 可靠验证码短信 | 普通/识别失败/歧义短信 |
|---|---|---|---|---|
| S01 / A | 开 | 开 | SIMPLIFIED：原有逐位精简格式 | IGNORE |
| S02 / B | 开 | 关 | FULL：原始正文 | IGNORE |
| S03 / C | 关 | 开 | SIMPLIFIED：原有逐位精简格式 | FULL：原始正文 |
| S04 / D | 关 | 关 | FULL：原始正文 | FULL：原始正文 |

- 两个开关始终独立可操作，互不修改保存值；状态来自同一 SettingsRepository StateFlow。
- 总运行开关关闭、正文为空或超过原输入上限仍先拒绝。FULL 仍受80个 UTF-16代码单元限制，不删除提示、不去空白、不改字母数字、不截断。
- 仅以现有 OtpDetector 的可靠结果精简；null（失败或歧义）按表处理，不调整识别算法。验证码数字沿用 V1.0 中文逐位读法。
- 两个默认值均为 true；原 `stage0` SharedPreferences、`otpOnlyEnabled` / `otpSimplifyEnabled` / `target` 等键继续使用，无新增迁移或启动重置。
- 升级保留运行、开机恢复、目标耳机及两个开关；已有 C 状态按新规则解释，保存值不变。

## 保护边界

SMS_RECEIVED、PDU、多段组合/防混发/防重复、离线TTS、PCM、MAY_DUCK、焦点恢复/取消、严格目标身份和实际路由、停止后不复活、开机对账均沿用。

保留80 UTF-16代码单元、PCM5秒/1MiB、接收起8秒预算、700ms清理余量和120秒PDU有效期。超限整条拒绝，字符合规不保证音频可播完。

本轮末期发现有效的重启/锁屏静置真实SMS在接收后1435ms发生临时焦点竞争，超出V1.0的1200ms启动窗口，导致恢复预算不足。为修复本阶段真实验收阻塞，在复现测试先FAIL后，仅把一次初始焦点窗口修正为1800ms；原等待算法、接收起点、MAY_DUCK/临时丢失恢复/永久丢失取消/路由及全部预算不改。不修改阶段0/V1.0历史文档，不把旧1200ms实现事实冒充当前值；这是实测驱动的启动调度常量修复，不是新增产品规则、队列或音频架构重构，详见[实现报告](stage1-report.md)。

版本固定 `3 / 2.0.0-stage1`；不改包身份、namespace、SDK、签名配置或权限。不新增 Service、网络请求、通知监听、统一队列或阶段2代码，T01～T13继续 TBD。

V1.0 43 PASS/2 SKIP仅为历史结果，不计入本轮。阶段1结论仅可为 PASS/PENDING/FAIL；人工真实短信及关键听感未完成时保持 PENDING，不进入阶段2。
