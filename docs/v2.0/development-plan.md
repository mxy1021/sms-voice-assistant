| 优先级 / 类型 | 验证事项 | 当前证据 |

## 阶段5：统一消息调度系统

主要任务：

- 统一消息数据模型。
- P0/P1 双逻辑队列。
- P0 FIFO。
- P1 FIFO。
- 验证码优先级调度。
- 非抢占式播放。
- 队列生命周期。
- 去重和过期机制。
- 队列溢出处理。
- 蓝牙和音频异常处理。
- 资源释放与异常恢复。

验收标准：

- 验证码优先于等待中的普通消息。
- 当前消息不会被验证码中断。
- 当前消息完成后立即优先调度 P0。
- P0 和 P1 内部顺序正确。
- 不出现重复、丢失或错序播报。
- 不发生音频资源泄漏。

# 验收解释与兼容要求

- 方案 A 的“当前消息完成”指正常消息调度；主动停止、总开关关闭、断连、路由不匹配、永久焦点丢失等安全事件仍须立即停止。
- 不为验证码优先级保存/恢复普通消息进度，不影响继承临时音频焦点丢失与恢复。
- 四种短信组合、微信和其他应用的全文播报均遵守已继承的80 UTF-16代码单元、PCM5秒/1MiB和8秒预算；安全拒绝不能标记为完整播报成功。
- 阶段5“不出现重复、丢失或错序”须按届时已确认的输入/过滤/去重/过期/溢出规则检查：按规则拒绝、过期或取消应有明确结果，不冒充完成，也不默认为意外丢失。产品标准不改写为无条件跨进程可靠投递承诺。
- V1.0 短信接收、原有音频/路由、签名/配置及 Debug/Release 隔离均须按实际变更回归；不重写接收模块，不改写旧验收证据。R15、L09 保持历史 SKIP。
- 自动化规则测试、构建/静态检查、真实短信、真实通知、后台条件、实际路由和人工听感分别记录，不能互相冒充证据；本轮没有执行这些工程/设备测试。
- “及时”“不发生明显重复”等用户原定标准保持原意；没有确认的时延阈值、窗口或覆盖数量不擅自数值化。
