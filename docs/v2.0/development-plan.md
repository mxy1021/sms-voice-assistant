# 十、V2.0 正式开发阶段划分

## 阶段0：项目准备与技术方案确认

主要任务：

- V1.0 稳定基线检查。
- V2.0 产品需求确认。
- 总体技术架构设计。
- 模块职责划分。
- 消息处理流程设计。
- 开发阶段和验收标准制定。
- Git 分支与版本管理准备。
- 正式文档归档。

验收标准：

- 需求文档完整。
- 技术架构清晰。
- 已确认规则与 TBD 明确区分。
- 各阶段任务和验收标准明确。
- GitHub 工程基线准备完成。

## 阶段1：短信播报规则升级

主要任务：

- 两个短信开关独立。
- 四种规则组合。
- 验证码精简及全文播报。
- 普通短信过滤和全文播报。
- 配置持久化及兼容。
- 自动化测试。
- 真机测试。

验收标准：

- 四种组合全部正确。
- 两个开关互不影响。
- V1.0 短信接收、TTS、蓝牙及音频焦点功能无回归。
- 完成必要的真实短信测试。

## 阶段2：微信通知技术验证

主要任务：

- NotificationListenerService 技术验证。
- 通知访问权限验证。
- 微信通知接收。
- 通知标题和正文提取。
- 联系人及群聊名称提取。
- Home、锁屏和后台监听验证。
- 离线 TTS 播报验证。
- 指定蓝牙耳机路由验证。

验收标准：

- 真实微信通知能够被接收。
- 能获取系统实际提供的可读通知内容。
- 能在目标设备后台及时处理。
- 能通过指定蓝牙耳机完整播报。
- 不发生扬声器泄漏。

## 阶段3：微信通知播报开发

主要任务：

- 微信通知解析模块。
- 联系人和群聊名称处理。
- 正文提取。
- 播报内容组合。
- 通知去重基础机制。
- 统一消息数据模型接入。

验收标准：

- 微信单聊通知正确播报。
- 微信群聊通知正确播报。
- 播报内容符合正式格式。
- 不发生明显重复播报。
- 不出现不同通知之间的内容错配。

## 阶段4：其他应用通知管理

主要任务：

- 获取本机应用列表。
- 展示应用名称和图标。
- 用户自主选择应用。
- 微信默认启用。
- 应用白名单管理。
- 非消息通知过滤。
- 权限撤销和恢复。
- 配置持久化。

验收标准：

- 用户能够选择需要播报的应用。
- 只处理已选应用。
- 能过滤非消息通知。
- 未选应用不进入播报流程。
- 权限撤销和重新授权后能够正确恢复。

## 阶段5：统一消息调度系统

主要任务：

- 统一消息数据模型。
- P0/P1 双逻辑队列。
- P0 FIFO。
- P1 FIFO。
- 验证码优先级调度。
- 非抢占式播放。
- 队列生命周期。
- 去重和过期机制。
- 队列溢出处理。
- 蓝牙和音频异常处理。
- 资源释放与异常恢复。

验收标准：

- 验证码优先于等待中的普通消息。
- 当前消息不会被验证码中断。
- 当前消息完成后立即优先调度 P0。
- P0 和 P1 内部顺序正确。
- 不出现重复、丢失或错序播报。
- 不发生音频资源泄漏。

## 阶段6：综合集成测试与正式验收

主要任务：

- 全部功能整合。
- 主界面和设置系统完善。
- 短信回归测试。
- 微信通知回归测试。
- 其他应用通知回归测试。
- 多消息调度测试。
- Home 和锁屏测试。
- 后台静置测试。
- 重启测试。
- 断 USB 测试。
- 蓝牙断连和重连测试。
- 音乐降低与恢复测试。
- Debug/Release 隔离检查。
- 正式文档归档。
- GitHub 正式发布。

验收标准：

- 所有强制功能测试通过。
- 关键后台场景通过真实设备测试。
- 不发生扬声器泄漏。
- 不破坏 V1.0 已验收功能。
- Debug 和 Release 安全检查通过。
- 完成正式验收报告。

# 验收解释与兼容要求

- 方案 A 的“当前消息完成”指正常消息调度；主动停止、总开关关闭、断连、路由不匹配、永久焦点丢失等安全事件仍须立即停止。
- 不为验证码优先级保存/恢复普通消息进度，不影响继承临时音频焦点丢失与恢复。
- 四种短信组合、微信和其他应用的全文播报均遵守已继承的80 UTF-16代码单元、PCM5秒/1MiB和8秒预算；安全拒绝不能标记为完整播报成功。
- 阶段5“不出现重复、丢失或错序”须按届时已确认的输入/过滤/去重/过期/溢出规则检查：按规则拒绝、过期或取消应有明确结果，不冒充完成，也不默认为意外丢失。产品标准不改写为无条件跨进程可靠投递承诺。
- V1.0 短信接收、原有音频/路由、签名/配置及 Debug/Release 隔离均须按实际变更回归；不重写接收模块，不改写旧验收证据。R15、L09 保持历史 SKIP。
- 自动化规则测试、构建/静态检查、真实短信、真实通知、后台条件、实际路由和人工听感分别记录，不能互相冒充证据；本轮没有执行这些工程/设备测试。
- “及时”“不发生明显重复”等用户原定标准保持原意；没有确认的时延阈值、窗口或覆盖数量不擅自数值化。
