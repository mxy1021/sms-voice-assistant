## 安装/工具故障历史（保留）

| 次序 | 现象 | 处理与结果 |
|---|---|---|
| 1 | 初次主APP `install -r` 返回INSTALL_FAILED_ABORTED | 用户准备手机后重试；主APP和测试APK均成功，V1.0配置/目标身份保留 |
| 2 | 新增SimplifyDuring后仅更新测试APK返回INSTALL_FAILED_ABORTED | 用户解锁后重试，普通流式安装仍无手机提示，等待120秒超时；摘要确认旧测试APK，未运行不匹配代码冒充通过 |
| 3 | 流式安装超时 | 改用 `adb install --no-streaming -r -t` 正常安装成功；摘要与本地测试构建一致；未卸载、清数据、绕过签名/权限或更改系统安全策略 |
| 4 | 本轮临时runner发现脚本使用行尾正则，未兼容ADB的CRLF | 在任何JUnit启动前即终止；改为splitlines逐行匹配后发现唯一目标runner，18项设备JUnit全部通过；不是产品缺陷 |
| 5 | Home后普通am kill未实际回收进程，脚本断言失败 | 不记回收PASS，不force-stop；改用instrumentation替换目标进程后重开，组合C持久值/UI/PID重建核对通过；自然系统回收仍未验证 |

原始安装失败/超时不记为当前未修复应用FAIL，也不删除。脱敏日志保留在被忽略的本地构建目录；不提交包含设备身份的异常全文。

真实功能失败另保留：SMS-000083（重启/15分钟断USB锁屏后无语音）及NotificationDelayedStartup旧策略FAIL，不与安装工具故障混算。准确时序、最小修复和复测见[测试结果](stage1-test-results.md)及[实现报告](stage1-report.md)。
