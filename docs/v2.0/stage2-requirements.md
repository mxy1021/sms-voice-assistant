# V2.0 阶段2｜验证需求

启动日期为 2026-11-24（Asia/Shanghai）。依据[正式开发计划](development-plan.md)、[决策台账](technical-decisions.md)及[阶段1.1关闭报告](stage1.1-closure-report.md)。后续用户决定优先于阶段0规划。D01～D18 继续有效，T01～T13 保持 TBD。阶段1.1 的5条短信待播规则适用于现有 SMS 队列。

## 验证目标

- 在 vivo X200 Pro（V2405A）、OriginOS 7、Android 17/API 37 通过 Android 通知监听接收真实微信通知，核验主用户安装包、授权、系统绑定、断开、重绑、撤权和重启恢复。
- 分别验证单聊、群聊、连续消息、通知更新、撤销、非消息、预览关闭、锁屏保护和空正文。记录实际可见字段、延迟、回调和进程状态，身份及内容缺失时保持未知。用户查看的系统通知和应用读取结果分别取证。
- 分别验证前台、Home、屏幕关闭、锁屏、后台静置、界面未打开和重启后已解锁但未打开本应用。记录实际静置时长、USB 与最近应用状态。以真实观测判断及时性。
- 核对 Android 17 上无可见 Activity 时的焦点申请、静音和实际语音。固定文本和真实通知分别计数，实际发声、完整听感、音乐降低恢复和无手机语音由用户确认。
- 在原位升级后核验短信入口、全部正式短信规则、指定耳机、原安全时限、配置持久化、五条等待队列及观察模式下的 SMS 隔离。

## 工程与隐私边界

沿用 `com.mxy1021.smsvoiceassistant`、版本 `3 / 2.0.0-stage1`、SDK `33 / 34 / 36` 及同一签名配置。新服务仅为 Debug 的系统绑定 `NotificationListenerService`。通知使用权由用户通过系统设置主动授予。服务本地处理回调，其他应用、其他 Android 用户以及历史通知均排除在原型范围外。

继承完整选文不超过80 UTF-16、完整 PCM 不超过5秒和1MiB、离线合成、原响度和四档增益、MAY_DUCK、严格指定耳机路由及安全终结。实验期间只有用户主动触发的固定句和一次性受控微信测试。正文、联系人、群名、账号、原始通知标识和完整 PCM 不落盘、不输出日志、不上传。保留现有 Android 与厂商保护、媒体音量、安全取消和 Release 功能。

阶段3～6对应正式格式、分类、缺字段、更新、撤回、去重、持久化、队列与其他应用管理规则仅记录观察。阶段2技术档位由目标设备实际证据决定，正式验收由用户确认。
