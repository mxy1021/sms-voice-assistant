## 使用

1. 在系统中配对目标蓝牙耳机，安装与现有版本相同签名的APK；升级使用保留数据更新，不卸载清数据。
2. 打开APP，正常授予短信和蓝牙连接权限，选择目标耳机并刷新。已配对不代表已连接；路由不匹配时不播报。阶段0旧耳机设置原位保留。
3. vivo OriginOS7请手动确认本应用“允许后台高耗电”和系统“权限管理→自启动”。重启后独立收信的本机实测条件是自启动开启；关联启动保持关闭也已通过，无需据此开启。“后台运行设置”打开公开应用信息入口，APP不能读取或自动修改该厂商设置。开启可能增加耗电。
4. 点击“测试耳机语音”，只播放固定人工文本。需要亲自确认完整耳机听感以及音乐降低/恢复；回调不能代替听感。
5. 手动打开“启用短信播报”；新安装和阶段0升级默认暂停。停止会取消在途播放并忽略后续短信。
6. 选择两个规则开关。Home、锁屏和正常进程重建保留配置；真实后台表现仍受当前系统设置约束。
7. “语音增益”仅有0、+3、+6、+9dB四档，默认0。基础响度处理仍生效；峰值保护会限制实际提升，不改变系统或播放器音量。
8. “界面显示模式”可选普通、深色或跟随系统，立即生效并保存，不影响后台短信处理。

| 仅播报验证码 | 精简验证码播报 | 可靠验证码SMS | 普通/识别不明确SMS |
|---|---|---|---|

两个规则默认开启，各自保存、始终可操作。已确认的验证码数字逐位朗读；常见数字码及部分字母数字混合码支持基础识别。未知/多候选在仅验证码开启时忽略，关闭时按清理后全文处理。仅明确验证码逐位转换，其余数字正常朗读；链接过滤不删除安全提示。联系人可选授权；无法可靠取名（包括未授权/无匹配/查询失败）时读“未知联系人，正文”，不朗读号码；已有V1.0保存值保留，但“关/开”组合现在按V2.0精简验证码。

**全文边界：**最多80个UTF-16字符包含联系人或未知提示及转换正文，只是文本上限；完整PCM还必须≤5秒、≤1MiB，并满足从接收起8秒总预算及清理余量。超限整条拒绝，在最近处理状态中提示，不截断。超出上述任一限制的SMS（包括混合验证码）可能无法播报；更短文本也可能因TTS冷启动或语速超时被整条拒绝。较长/任意长度全文不在本阶段MVP范围，尚未实现。

“开机后恢复工作状态”默认关闭：重启后在首次进程处理任何短信前暂停；打开则保留上次启用/暂停状态。使用系统开机计数对账和解锁后的开机接收器，不处理解锁前短信。应用内恢复开关不会授予厂商自启动许可。H07实测由SMS Receiver先冷启动进程，开机广播事件随后才到；无需先等开机广播或每次重启手动开APP。强行停止和厂商限制不保证恢复，开机恢复不等于后台保活。

## 架构与隐私

沿用阶段0已验证路径：SMS_RECEIVED → 新PDU → 规则 → 指定蓝牙连接/预期路由 → 严格离线中文TTS → 内存PCM → MAY_DUCK焦点 → AudioTrack静音实际路由验证 → 播放/清理。实际写入前重新检查运行许可、权限及路由；阶段1.1采用最多5条待播的非抢占优先队列，验证码优先，同级FIFO；满时拒绝新消息，等待计入各自原广播预算，安全停止清空旧消息。只保证已进入APP的待播消息排序；真实117～119入口串行，未取得真实短信重排证据。

请求 RECEIVE_SMS、BLUETOOTH_CONNECT、RECEIVE_BOOT_COMPLETED，以及可选 READ_CONTACTS（仅用户主动授权后按当前短信号码查询，不缓存联系人）。无INTERNET、历史短信数据库、短信上传、正文/验证码/音频文件保存、常驻Service、FGS、后台轮询、系统媒体音量修改或播放器控制。基础响度标准化、用户0/+3/+6/+9dB增益及平滑峰值保护只处理当前会话的内存PCM，默认用户增益0dB；不叠加硬件LoudnessEnhancer，缓冲随会话清理。音乐降低及恢复由系统/播放器处理。阶段0历史诊断工具仅Debug页面可见，正式界面没有A/B模式；正式音频固定MAY_DUCK。

目标设备为vivo X200 Pro / OriginOS7 / 实读Android17 API37，min/target/compile固定33/34/36。Android17有[独立后台音频限制](https://developer.android.com/about/versions/17/changes/bg-audio)，本机历史成功不代表所有设备兼容。动态断连/切路由仍有系统回调及缓冲窗口，需要真实安全回归，不承诺零泄漏。
